# Расчёт и подтверждение покупки

Стэк: Ruby 3.3, Sinatra, Sequel, SQLite. База `db/test.db` — копия исходной `TEYCA 6/test.db`
(путь можно переопределить через `DATABASE_PATH`).

```sh
bundle install
bundle exec rackup -p 9292   # POST /operation, POST /submit
bundle exec rspec            # схема базы из ТЗ без данных, записи создают фабрики (spec/factories)
bundle exec rubocop
```

## Docker

```sh
docker build -t purchases .
docker run -p 9292:9292 -v "$PWD/db:/app/db" purchases   # контейнер работает с локальной db/test.db
```

## Особенности реализации

1. **Скидки уровня и товара складываются:** Silver 5% + Хлеб 15% = 20%.
2. **Кэшбек считается от цены после скидки и применения баллов.**
3. **Списание баллов уменьшает кэшбек пропорционально.** На оплаченную баллами часть кэшбек
   не начисляется, списание распределяется по товарам программы пропорционально:
   `cashback × (1 − write_off / allowed_write_off)`.
   В `operations.cashback` до подтверждения хранится точный кэшбек (31.7), до целых баллов округляется
   только итог, чтобы двойное округление вниз не теряло балл (19.99 → 19 → 18 вместо 19).
4. **Общий процент** скидки считается от суммы до скидки, кэшбека — от суммы к оплате.
5. **Округление.** Деньги и проценты — до 0.01 (BigDecimal, половина вверх). Стоимость позиции
   (цена × количество) округляется до копеек, поэтому сумма к оплате всегда в копейках, даже если цена
   пришла с лишними знаками или количество дробное (10.12 × 0.333 → 3.37). Баллы целые: начисляемый
   кэшбек и лимит списания округляются вниз (31.7 → 31), чтобы не начислить и не разрешить списать больше
   заработанного.
6. **Из `user` в `/submit` используется только `id`:** баланс и уровень читаются из базы.
7. **`quantity` может быть дробным** (весовые товары, 0.5 кг сахара), но должно быть больше 0.
   **Цена 0 допустима** — бесплатный товар, например подарок: его стоимость, скидка и кэшбек равны 0.
8. **Числа принимаются только числами JSON:** строки (`"42"`) отклоняются.
    Id и баллы (`write_off`) должны быть целыми, `2.0` отклоняется. Цена и количество могут быть дробными.
9. **`/submit` идемпотентен по `operation_id`:** повтор с тем же `write_off` возвращает прежний ответ
    и не меняет баланс. `/operation` не идемпотентен: каждый запрос создаёт новую неподтверждённую операцию.
10. **Поля ответа совпадают с колонками БД** (`check_summ`, `cashback`, `discount_percent`,
    `allowed_write_off`, …). Уровень пользователя отдаётся названием (`user.level: "Bronze"`).

## Ошибки

Ответ — `{"status": <код>, "message": "..."}`:

- **400** — некорректные параметры; в `errors` перечислены все ошибки сразу, с путём к полю:
  `"Параметр positions[1].price должен быть числом"`;
- **404** — пользователь или операция не найдены (в т. ч. чужая операция);
- **422** — операция уже подтверждена с другим списанием, списание выше лимита или баланса.
